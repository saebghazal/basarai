# Data Model: Platform Foundation (003)

**Date**: 2026-10-07 | **Plan**: [plan.md](./plan.md)

This feature stores no product data (the database schema is owned by `specs/002-database`). Its
"entities" are configuration, contract, and record artifacts. Each is defined here with fields and
validation rules; the exact files are listed in [plan.md](./plan.md).

## 1. Application

| Field | Values / rules |
|-------|----------------|
| name | `web`, `api`, `worker` |
| source | `apps/web`, `apps/api` (target `api`), `apps/api` (target `worker`) |
| image | `ghcr.io/saebghazal/basar-<name>:<git-sha>`; immutable; non-root user |
| settings | exactly the variables assigned in [contracts/configuration.md](./contracts/configuration.md) |
| health | web: `/api/health`; api: `/health/live`, `/health/ready`; worker: heartbeat age < 30 s |
| public | web only (FR-035) |

Rule: an application refuses to start if a required setting is missing (FR-005).

## 2. Environment

| Field | Values / rules |
|-------|----------------|
| name | `local`, `staging`, `production` |
| data platform | local Supabase CLI stack; `basar-staging`; `basar-prod` (M8) |
| hosting | local processes / Docker; Bunny apps `basar-web-staging` + `basar-worker-staging` at `https://staging.basarai.app`; production apps at M8 |
| secrets store | `.env` files (local, git-ignored); GitHub environment secrets + Bunny app secrets |
| last good version | SHA of the most recent GitHub Deployment for that environment with status `success` (GitHub Deployments API), created by the deploy workflow after a passing health gate |

Rule: no credential is shared between environments (FR-032).

## 3. Interface contract

| Field | Rules |
|-------|-------|
| document | `packages/api-client/openapi.json`, generated by the API, sorted keys |
| version | `info.version` = `0.<milestone>.<n>`; this feature publishes `0.0.1` |
| generated client | `packages/api-client/src/schema.d.ts` + `src/index.ts` client factory |
| error codes | `ErrorCode` enum in the document; each needs `errors.<code>` in both catalogs |
| drift rule | regenerated document and client must equal the committed files (FR-014) |

Shared schemas defined in [contracts/http-baseline.md](./contracts/http-baseline.md): `ErrorEnvelope`,
`ErrorCode`, `Page`, `HealthStatus`, `SessionInfo`, the twelve shared identifier enums (`AppRole` …
`CategoryId`, values equal to the 002 database enums), and parameters `Cursor`, `Limit`,
`IdempotencyKey`.

## 4. Translation catalog

| Field | Rules |
|-------|-------|
| files | `apps/web/src/messages/en.json`, `ar.json` |
| structure | nested objects; identical key trees in both files |
| namespaces | `common`, `nav`, `shell`, `language`, `errors` (one key per `ErrorCode`) |
| check | `i18n:check` fails on missing, extra, or unused keys and on missing error codes (FR-017, FR-028) |

## 5. Decision record (ADR)

| Field | Rules |
|-------|-------|
| path | `docs/adr/NNNN-kebab-title.md` |
| sections | Status (`proposed`/`accepted`/`superseded`), Date, Context, Decision, Consequences, References |
| required for M0 | 0001 database access model; 0002 dependency baseline (FR-038) |

## 6. Verification record

| Field | Rules |
|-------|-------|
| path | `docs/verification/m0-checkpoints.md` (one table) |
| row | `id` (V-01…V-08), `question`, `outcome` ∈ `confirmed` / `changed` / `blocked`, `date`, `evidence` (link or command output summary, no secrets), `follow_up` (link to plan/spec change when `changed`) |
| gate | all eight rows have an outcome before M1 starts (SC-010) |

State per row: `open` → `confirmed` | `changed` (requires follow-up link) | `blocked` (requires
fallback from plan §16.2 recorded).

## 7. Release image

| Field | Rules |
|-------|-------|
| tag | full git SHA of a commit on `main` |
| labels | `org.opencontainers.image.revision`, `.source`, `.created` |
| contents | no `.env`, no source maps with secrets, no test fixtures; `BUILD_SHA` baked as env |
